# Чтение локальной аудиотеки

Статус: Запланировано.

## Цель

Пользователь получает список доступных аудиофайлов на телефоне для последующего воспроизведения
и добавления в плейлисты.

## Границы функции

Первая версия работает на Android и читает аудиозаписи, доступные через системный индекс `MediaStore.Audio`.

Функция включает запрос доступа, чтение метаданных, отображение списка и повторное чтение по действию пользователя.

Результат содержит все доступные аудиозаписи выбранной коллекции. Ограничение только записями с признаком
`IS_MUSIC` не применяется.

Файлы, отсутствующие в системном индексе, не входят в результат.

Ручной выбор файлов и папок, воспроизведение, поиск, пользовательские фильтры и добавление композиций
в плейлисты реализуются отдельно.

## Основной сценарий

1. Пользователь открывает раздел "Музыка на телефоне".
2. Приложение объясняет необходимость доступа к музыке и аудио.
3. Пользователь нажимает "Найти музыку".
4. Приложение проверяет разрешение и при необходимости показывает системный запрос.
5. После предоставления доступа приложение читает доступные аудиозаписи.
6. Пользователь видит список или сообщение об отсутствии найденных файлов.

При уже предоставленном разрешении повторный системный запрос не выполняется.

## Правила доступа

Разрешение запрашивается в контексте чтения аудиотеки после явного действия пользователя.

Отказ в доступе не блокирует создание и просмотр плейлистов.

Перед каждым чтением проверяется актуальное разрешение.

Отсутствие разрешения отличается от успешно загруженного пустого списка.

После обычного отказа пользователь может повторить запрос.

Если системный запрос больше недоступен, приложение предлагает открыть настройки приложения.

После возвращения из настроек разрешение проверяется повторно. Системный диалог автоматически
не открывается.

## Данные аудиозаписи

Запись содержит:

- `id` — непрозрачный строковый идентификатор.
- `uri` — адрес доступа к содержимому.
- `title` — название из метаданных, если оно известно.
- `fileName` — имя файла, если оно известно.
- `artist` — исполнитель, если он известен.
- `durationMs` — длительность в миллисекундах, если она известна.

Отсутствующие необязательные метаданные представлены явно.

При отсутствии названия интерфейс использует имя файла. Если оба значения отсутствуют,
отображается "Аудиофайл без названия".

При отсутствии исполнителя отображается "Исполнитель не указан".

Записи с одинаковыми названиями отображаются отдельно.

Повторное чтение одной записи системного индекса возвращает тот же идентификатор.

Удаление файла, повторное добавление или перестроение системного индекса могут изменить его
платформенную идентичность.

## Чтение и обновление

Список представляет снимок системного индекса на момент чтения.

Пользователь может повторить чтение действием "Обновить список".

Повторное чтение заменяет предыдущий снимок и не добавляет копии уже отображаемых записей.

Повторный запуск одного действия блокируется на время его выполнения.

Устаревший результат и результат после размонтирования не обновляют состояние интерфейса.

Функция читает метаданные. Аудиофайлы сохраняются на исходных местах.

## Состояния интерфейса

Интерфейс различает:

- Ожидание действия пользователя.
- Запрос разрешения.
- Чтение аудиотеки.
- Успешно загруженный список.
- Успешно загруженный пустой список.
- Отказ в разрешении.
- Необходимость изменить разрешение в настройках.
- Ошибку чтения.

Во время чтения отображается сообщение "Ищем аудиофайлы...".

Успешный пустой результат сопровождается сообщением "Доступные аудиофайлы не найдены".

## Обработка ошибок

При отсутствии доступа приложение объясняет необходимость разрешения и предоставляет доступное
следующее действие.

При ошибке чтения отображается сообщение "Не удалось загрузить список аудиофайлов. Попробуйте ещё раз"
и кнопка "Повторить".

Потеря разрешения во время чтения обрабатывается как отсутствие доступа.

Ошибка доступа или чтения не преобразуется в пустой список.

Технические подробности ошибок пользователю не показываются.

## Доступность

Основные действия имеют видимые подписи, понятные роли и состояния.

Загрузка, отказ в доступе и ошибка обозначаются текстом.

Длинные названия переносятся и сохраняют читаемость при увеличении системного шрифта.

Список доступен для прокрутки.

Область нажатия основных действий составляет не менее 48 x 48 dp.

Порядок фокуса соответствует интерфейсу. Сообщения о состоянии доступны через TalkBack.

## Критерии приёмки

### Предоставление доступа

Дано: разрешение отсутствует.

Когда: пользователь запускает поиск и предоставляет доступ.

Тогда: приложение читает аудиозаписи и отображает результат.

### Отказ в доступе

Дано: пользователь отказал в разрешении.

Когда: системный запрос завершается.

Тогда: приложение объясняет отсутствие доступа, предоставляет следующее действие
и сохраняет доступность плейлистов.

### Пустой результат

Дано: разрешение предоставлено, системный индекс не возвращает аудиозаписей.

Когда: чтение завершается успешно.

Тогда: отображается сообщение об отсутствии найденных файлов.

### Неполные метаданные

Дано: у записи отсутствуют название или исполнитель.

Когда: запись отображается.

Тогда: интерфейс использует предусмотренные подписи и сохраняет запись в списке.

### Одинаковые названия

Дано: системный индекс содержит разные записи с одинаковым названием.

Когда: чтение завершается.

Тогда: записи отображаются отдельно.

### Повторное чтение

Дано: список уже загружен, состав системного индекса изменился.

Когда: пользователь обновляет список.

Тогда: интерфейс отображает новый снимок без накопления копий предыдущего результата.

### Ошибка чтения

Дано: источник данных возвращает ошибку.

Когда: чтение завершается.

Тогда: отображаются сообщение об ошибке и повторная попытка.

## Проверка функции

Юнит-тесты проверяют сценарий доступа, выбор разрешения по версии Android, обработку результатов
и преобразование метаданных.

Интеграционные тесты проверяют взаимодействие сценария с адаптерами через явные границы зависимостей.

Компонентные тесты проверяют действия пользователя, состояния интерфейса и игнорирование устаревших результатов.

Нативные интеграционные проверки используют подготовленные аудиофайлы и настоящий `MediaStore`.

Проверки охватывают поддерживаемые ветви Android для разрешений и адресации коллекций.

На устройстве или эмуляторе проверяются системные диалоги, отзыв разрешения, возвращение из настроек,
TalkBack и увеличение шрифта.

Результаты нативной проверки фиксируются отдельным протоколом после появления реализации.
