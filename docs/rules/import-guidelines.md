# Правила оформления импортов

## Пути

Алиас `@/` обозначает каталог `src/`.

Внутренние модули из `src/` импортируются через алиас. Правило действует также для соседних файлов и тестов.

Путь указывает конкретный модуль от корня `src/`.

Расширения `.ts`, `.tsx`, `.js` и `.jsx` в импортах исходного кода не указываются.

Расширения JSON и ресурсов сохраняются.

Для файлов вне `src/` допускаются относительные пути. Это относится, например, к корневым `App.tsx` и `app.json`.

Конфигурационные файлы, выполняемые Node.js, используют имена пакетов и относительные пути.

## Импорты типов

Зависимости, используемые только как типы, оформляются отдельной декларацией `import type`.

Значение импортируется обычной декларацией `import`.

## Порядок

1. Встроенные модули Node.js с префиксом `node:`.
2. Внешние библиотеки.
3. Внутренние модули через `@/`.
4. Допустимые относительные импорты.

Основные группы разделяются пустой строкой.

Внутри каждой основной группы сначала размещаются импорты значений, затем отдельные декларации `import type`.

Внутри каждой подгруппы импорты упорядочиваются по пути модуля. Между подгруппами значений и типов пустая строка не добавляется.

Порядок импортов с побочными эффектами учитывает требования инициализации модулей.

## Архитектура

Использование алиаса сохраняет границы зависимостей, определённые ADR-0001.

Расположение модуля в другом каталоге не даёт дополнительного права обращаться к его внутренней реализации.

## Форматирование

Отступы и переносы строк определяются конфигурацией Prettier.

Форматирование запускается командой `npm run format`. Проверка форматирования запускается командой `npm run format:check`.

## Автоматические проверки

Порядок основных групп, подгрупп значений и типов проверяется Prettier с плагином `@ianvs/prettier-plugin-sort-imports`.

Подгруппы импортов типов задаются через `<TYPES>` в конфигурации Prettier. Импорты значений и типов сохраняются отдельными
декларациями.

Пути внутри каждой подгруппы сортируются без учёта регистра с естественным порядком чисел.

Импорты с побочными эффектами сохраняют порядок и образуют границы сортировки.

ESLint проверяет расширение в статических импортах и реэкспортах, запрещает относительные импорты из файлов внутри `src/`
и требует отдельные декларации `import type`.

Команда `npm run lint:fix` применяет доступные автоматические исправления. Оставшиеся нарушения исправляются вручную.

Соблюдение архитектурных границ дополнительно проверяется при ревью.
