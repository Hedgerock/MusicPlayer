# ADR-0005: Доступ к локальной аудиотеке Android

## Статус

Принято.

## Контекст

На момент принятия решения приложение поддерживает создание и сохранение пустых плейлистов.

Модуль музыкальной библиотеки отсутствует. Приложение должно получать метаданные аудиофайлов
на устройстве и предоставлять их пользовательским сценариям.

Основной платформой является Android. Приложение использует React Native с новой архитектурой.

Доступ к аудиофайлам зависит от системных разрешений и состояния системного индекса.

Слои `domain` и `application` сохраняют независимость от Android и React Native.

## Решение

### Источник данных

Источником локальной аудиотеки Android является `MediaStore.Audio`.

Чтение выполняется через `ContentResolver`.

Приложение получает метаданные и адреса содержимого. Файлы сохраняются на исходных местах.

Для доступа к содержимому используются `content://` URI. Абсолютный файловый путь
не является контрактом библиотеки.

Результат чтения представляет снимок системного индекса.

### Граница платформенной интеграции

Запрос к `MediaStore` реализуется собственным Kotlin TurboModule.

Контракт нативного модуля задаётся типизированной спецификацией Codegen. Имя файла спецификации
начинается с `Native` согласно требованиям инструмента.

Нативный запрос выполняется вне главного потока Android.

Нативная реализация освобождает курсор после завершения чтения и управляет ресурсами фонового выполнения.

Адаптер в `library/infrastructure` вызывает нативный модуль и преобразует платформенные данные
в модель библиотеки.

Сценарии получают источник аудиозаписей и управление доступом через контракты `application/ports`.

Компоненты вызывают подготовленные операции. Сборка зависимостей выполняется в `app`.

### Разрешения

Проверка и запрос разрешений выполняются Android-адаптером на основе `PermissionsAndroid`.

Для чтения аудиофайлов других приложений используются:

| Версия Android | Разрешение              |
| -------------- | ----------------------- |
| API 24–32      | `READ_EXTERNAL_STORAGE` |
| API 33 и выше  | `READ_MEDIA_AUDIO`      |

Декларация `READ_EXTERNAL_STORAGE` ограничивается `maxSdkVersion="32"`.

Приложение запрашивает доступ после действия пользователя, связанного с чтением аудиотеки.

Разрешение на доступ ко всем файлам и разрешение на запись для этого сценария не используются.

Перед чтением проверяется актуальное состояние доступа. Нативная реализация также обрабатывает
отказ в доступе во время запроса.

Отказ, блокировка системного запроса и ошибка чтения передаются как разные результаты сценария.

### Идентичность аудиозаписей

Идентификатор формируется из идентичности записи `MediaStore`, включая том и идентификатор записи.

Числовой идентификатор платформы преобразуется в строковое представление без передачи через
числовой тип JavaScript.

Слои `domain` и `application` рассматривают идентификатор как непрозрачную строку.

Название, исполнитель и позиция в списке не используются как идентификатор.

Адрес содержимого строится для коллекции и записи, из которых получены метаданные.

Идентичность записи не считается постоянной после удаления файла или перестроения системного индекса.

### Хранение и состояние

Первый сценарий читает библиотеку из `MediaStore` без постоянного кэширования её метаданных в SQLite.

Пользовательские плейлисты продолжают храниться в рабочей базе SQLite.

Загруженный снимок и состояния чтения принадлежат представлению библиотеки согласно ADR-0004.

Системное разрешение проверяется через платформенный API и не заменяется сохранённым флагом приложения.

## Рассмотренные альтернативы

### Storage Access Framework

Предоставляет пользователю выбор файлов или каталогов.

Этот подход соответствует ручному добавлению выбранных документов. Для получения списка из системной
аудиотеки выбран `MediaStore`.

Ручной выбор файлов может быть добавлен отдельным сценарием.

### Сторонняя библиотека доступа к медиа

Сокращает объём собственного нативного кода, но добавляет зависимость от её контракта
и совместимости с версиями React Native и Android.

Для узкого сценария чтения метаданных выбран собственный адаптер к системному API.

## Последствия

Приложение использует системный индекс и стандартную модель разрешений Android.

Границы TypeScript-кода позволяют проверять сценарии без нативного окружения.

Проект получает собственный Kotlin-код, требующий сопровождения, сборки и нативных проверок.

Полнота результата зависит от системного индекса и предоставленного доступа.

Изменения файлов становятся доступны при повторном чтении.

## Не входит в решение

- Реализация библиотеки на iOS.
- Выбор аудиодвижка и воспроизведение.
- Добавление композиций в плейлисты.
- Постоянный кэш метаданных и изменение схемы SQLite.
- Наблюдение за изменениями файлов в фоне.
- Ручной выбор файлов и каталогов.
- Конкретная библиотека навигации.
- Поиск и пользовательские фильтры.
